# SQL 推理与修复配置评估

本页报告已知开发题上的配置选择，不定义“生产准确率”。

## 协议

- 26 个自然语言问题，覆盖库存、工单、物流、账单和制造业。
- 每题两个固定数据库实例；每个问题/实例运行三次，共 156 次。三个随机种子为 917、918、919。
- 模型 `qwen3:14b`，Ollama Q4_K_M；启用推理、SQL 文本输出和通用语义检查提示。每次请求最多 8192 输出 token、16384 上下文、120 秒；每个任务最多三轮 SQL，传输重试最多三次/轮。
- 不叠加关系计划、探查或独立模型核对器。不向运行时提供参考 SQL 或 Python 答案。
- 比较配置为 `qwen2.5-coder:14b` + 同一语义提示 + 2048 输出 token + 一轮 SQL。三组既有记录合计 156 次，答对 102 次。
- 检查两配置的第一轮提示哈希、题目/实例/重复编号完全对应。模型、推理、采样、预算和修复策略一起变化，因此这是配置比较，不是推理功能的单因素消融。

正确候选须与独立 Python 结果匹配，包括列名、行顺序、重复行和值。模型生成的同一 SQL 还会在两个数据实例上离线执行；这只能增加对这些实例的信心，不能证明所有数据库上的语义等价。

`accepted_correct` 表示控制器保留了一个离线判定正确的候选，**不表示自动发布**。全部通用任务仍要求审核。执行错误修复数由第一条查询和最终候选比较得到，不能把它当成独立随机对照的修复收益。

## 完整结果与选择

| 配置 | 正确 / 错误 / 停止 | 全三次均正确的题目/实例组 | 模型请求 | p95 延迟 |
|---|---:|---:|---:|---:|
| Coder 14B，单轮 | 102 / 42 / 12 | 33/52 | 156 | 2.12 秒 |
| Qwen3 14B，非推理与修复 | 108 / 48 / 0 | 36/52 | 161 | 2.23 秒 |
| Qwen3 14B，推理与修复 | **142 / 13 / 1** | **43/52** | 163 | **74.83 秒** |

每行 156 次。推理配置正确率 91.03%，首条查询正确 138 次，最终正确 142 次：观察到 4 次从错误到正确的修复，没有首条正确但最终丢失的情况。它仍保留 13 个错误候选，因此不能自动发布通用答案。账单 35/48、制造业 35/36，其余三个领域各 24/24。

推理配置相对 Coder 增加 25.64 个百分点；按 26 个问题簇 bootstrap 的描述性 95% 区间为 [8.97, 42.31]。非推理相对推理下降 21.79 个百分点，区间 [-40.38, -5.77]。这些是已知开发题上的配置差异，不能外推为未见数据库。

推理配置共报告 68377 输入 token、331914 输出 token；非推理输出 12314 token。推理 p50 为 28.22 秒。非推理对照使用相同模型 digest、首轮提示和三轮修复，但温度为 0、超时 30 秒、观察到的默认上下文为 32768；推理配置使用采样和 16384 上下文。因此也不能把两者差异全部归因于单一“thinking”开关。贪心重复仅表示观察到的稳定性。

**展示选择：推理配置 + 异步任务 + 通用结果人工审核。** 不叠加未证明收益的探查、关系计划或第二个模型核对器。代价是明显增加的等待和 token；没有云端定价时不编造美元成本。

主要残留失败是业务条件遗漏，而不只是 SQL 语法。例如 invoice_balance 仅 1/6 正确，部分查询虽消除了连接放大，却漏掉 settled 状态筛选。展示额外提供可见业务字典，这属于应用上下文，不属于本次纯 SQL 对照协议。

## 重现

```bash
PYTHONPATH=src:. python scripts/run_quality_regression.py \
  --output outputs/validation/quality_regression_fresh --repeats 3
```

需要本地 Ollama 已安装 `qwen3:14b`。使用新输出目录，保留所有失败。运行目录包含模型 digest、参数、源码快照、数据库快照、计划顺序、全部轨迹和汇总。代码和数据的结束哈希必须与开始一致。

比较脚本 `scripts/summarize_quality_comparison.py` 核对本次固定目录中的全部配对记录，再按问题簇进行 bootstrap。这里的置信区间描述此开发集上的差异，不覆盖模型选择与数据反复调试带来的选择偏差。

最早的账单、制造业测试曾作为新 schema 检查；其失败已经用于本次改进，因此本次不能再称为未见测试。历史 BIRD 500 题没有在此新配置下重跑，不能用这里的结果替代它。

配置依据：[Qwen3-14B 官方模型卡](https://huggingface.co/Qwen/Qwen3-14B)区分推理与非推理模式，并给出推理模式的采样建议。本项目采用其采样参数，但自行限制输出与等待预算；没有复现官方评测分数，也没有采用官方所有任务的推荐长度。


## 额外的数据变化检查

`scripts/check_billing_query_robustness.py` 将三个配置保存下来的全部账单候选，在 24 个新数据实例上重放，不进行新的模型推理。覆盖空明细、并列最大值、非整数百分比、可空关联键、相同金额的不同记录，以及固定种子的稀疏/密集明细。

这是 8 个已知问题的数据稳健性检查，不是新增 24 道问题，也不是公开基准。每配置 48 个原始候选分别接受 24 次检查；原控制器停止的候选仍计作失败。报告分别列出原实例正确数、新实例正确数，以及原两个实例加 24 个新实例全部正确的候选数。严格通过要求保留原实例的正确性。

负对照测试证明：一个整数除法查询可以在原来的两个实例都正确，却把新实例的 12.5% 算错；另一个测试检查 NULL 关联键导致的 `NOT IN` 问题。负对照是测试评估器的手写查询，不计为模型输出。

实际重放结果：Coder 24/48、推理 Qwen3 35/48、非推理 Qwen3 24/48 候选在原两个和新增 24 个实例上全部正确，原本正确候选没有新增失败。总计 3456 次离线检查、0 次新推理；SQL 停止记录仍计入分母。源码、输入轨迹和数据库哈希检查通过。这个结果没有解决原有错误，也不证明所有数据分布上的正确性。
