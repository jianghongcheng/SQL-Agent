# 多维 Agent 验收实现与实际运行

本页保留 v1 基线。两处缺口的后续修复与同协议 v2 结果见 [修复报告](MODEL_RECOVERY_FIX.md)。

这是离线工程证据，不是生产认证。指标来源见 [论文与代码证据](AGENT_PRODUCTION_EVALUATION_EVIDENCE.md)。本次不修改部署放行策略，不设未经业务确认的“生产合格线”。

## 已落地的评测

运行器：`scripts/validate_agent_reliability.py`；评分与聚合：`src/geomed_copilot/agent_evaluation.py`。

- **实际调用路径**：注册任务 → `JobPipeline` → 真实模型规划 → SQLite 执行 → 独立模型核对 → 放行/审核结果。不是用另一个模拟 Agent 代替服务逻辑。没有经过 HTTP 与 worker 队列，延迟仅代表 pipeline。
- **环境隔离**：每次完整任务重建独立业务 SQLite 与任务库；比较业务库运行前后 SHA-256。任务库写入是允许的副作用。此检查不覆盖网络泄露、行级权限或完整租户隔离。
- **结果评分**：模型运行结束后才执行参考 SQL；检查列、重复行、约定顺序与值。候选正确、控制器保留候选、实际自动发布分别记录。停止任务按明确拒绝原因评分，基础设施异常不能冒充正确拒答。
- **重复可靠性**：所有任务/场景组合重新完整运行 3 次；报告三个试验全部成功和至少一次成功的比例，对应 k=3 的经验 all-k/any-k。每次重建环境并重新调用模型，任务内部三次修复不算三次试验。temperature=0，因此不是独立随机采样概率的估计；不对这些相关小样本套用 iid 置信区间。
- **故障与改写**：三个有效任务全部做同义改写、主模型超时、核对器残缺 JSON、核对器 HTTP 429；三个错误过滤任务注入可执行但错误的 SQL。记录是否真正触发注入、是否恢复、是否停止且未发布。异常注入不包含真实等待时间，不能推导网络超时延迟。
- **成本**：保存所有模型输入、响应、调用角色、耗时、可观测输入/输出 token，失败与核对调用计入。缺失 usage 单列；无硬件、电价和人工审核成本，金额为 null，不能称免费。所有调用原始记录供重算。
- **复现**：运行前固定任务、场景、模型 digest、源码 SHA-256、重复次数；每个 episode 独立 JSON，最终检查源码未变。

21 个已有合成任务 × 3 次正常试验，加 3 个有效任务 × 4 个额外场景 × 3 次，以及 3 个错误过滤任务 × 3 次，共 **108 次完整任务、36 个任务/场景组合**。正常任务覆盖全部已有案例，不按结果挑选；它们是已知回归题，不是独立留出集。正常任务名中的 missing_column 等是历史命名，本次 normal 场景不给初始错误 SQL，由模型重新生成。

## 多实例评分器校验

`scripts/validate_sql_grader.py` 使用独立 Python 过滤规则作为期望值，在 6 份相同 schema、不同数据的实例上执行 5 条 SQL，共 30 次评分检查。包括边界值、重复值、空值、排序和空结果。正确 SQL 在全部实例通过；四条错误 SQL 都能通过基础实例，却无法通过完整测试套件。这借鉴 SQL distilled test-suite 的多实例思想，不是直接运行官方 Spider 测试套件。

这只是我们编写的正反例校验，没有人工盲审，也不代表任意业务 grader 已校准。开发时首先只有 5 份实例，断言暴露出排序错误未被区分；补入两条不同有效值的排序实例后，才通过校验。原始结果见 `outputs/validation/sql_grader_v1/result.json`。

## Mini-Interact 可用性核查

公开数据固定版本 `088b3787303e69129e395a9f712902670339ef72`，下载了 README 和题目文件。[官方说明](https://huggingface.co/datasets/birdsql/mini-interact/blob/088b3787303e69129e395a9f712902670339ef72/README.md) 明确：参考 SQL 与验收测试不随公开题目提供，通过邮件自动回复取得。没有发送邮件。

运行器逐题审计非空参考 SQL、非空测试和唯一 ID；缺失条件时 `ready_to_score=false`、`score=null`。这只是可用性审计，并未完成 Mini-Interact 适配、互动用户模拟器或官方评分器集成。绝不能把空测试视为通过，也不能把 public ambiguity 标注里的参考片段直接塞给 Agent 冒充正常输入。公开库文件可获得，但本轮没有下载数据库或执行外部题目。

## 复现

在仓库根目录，安装项目且本地 Ollama 有 qwen3:8b：

```bash
PYTHONPATH=src:. python scripts/validate_agent_reliability.py --output outputs/validation/agent-reliability-new
PYTHONPATH=src:. python scripts/validate_sql_grader.py --output outputs/validation/sql-grader-new/result.json
```

运行器输出目录必须不存在。Mini-Interact 题目文件需另从上述固定版本取得，置于 `data/local/mini_interact/mini_interact.jsonl`，才能附带可用性审计。没有外部文件时不会生成该审计。

## 仍然不能宣称的能力

没有验证完整生产端到端 SLO、真实业务效用、人工交接完成、租户级授权、提示注入防御、网络泄露防御、长期负载、模型更新漂移、隐藏测试泛化、业务成本/风险阈值。遇到故障停止与恢复是不同指标。全部转审核时自动发布的条件正确率没有定义，不能记成 100%。

## 本次实测结果

完整结果：`outputs/validation/agent_reliability_v1/summary.json`；逐题文件、manifest、coverage audit 和 run.log 在同目录。108 个唯一 episode 全部完成，没有遗漏或重复，运行源码哈希检查通过。完整回归 **92 passed**。

| 维度 | 观察值 | 含义 |
|---|---:|---|
| 正常可回答任务 | 候选正确 45/45，控制器保留 42/45 | 正确候选也可能被核对器拒绝；不是用户拿到答案的比例 |
| 正常应拒绝任务 | 18/18 明确拒绝 | 只覆盖写操作和不支持的外部上传请求，不代表提示注入安全性 |
| 正常任务经验 pass^3 | 20/21 组；其中可回答任务 14/15 组 | 同一道 orders:contract_alias 在三次试验中都被核对器 STOP，候选 SQL 实际正确 |
| 同义改写 | 9/9 正确且保留 | 仅三个简单任务的预设等义改写 |
| 错误 SQL 注入 | 9/9 修复正确且保留 | 三种指定错误过滤，不代表自然错误恢复率 |
| 主模型超时、核对器残缺 JSON、核对器 429 | 各 9/9 停止；恢复各 0/9 | 没有异常放行，但业务任务没完成 |
| 业务库副作用 | 108/108 前后文件哈希相同 | 此运行未修改业务数据库；未验证完整安全边界 |
| 自动发布 | 0/108；条件正确率 null | 全部进入审核，不能声称自动交付成功 |
| 实际模型调用 | 162 次，另有 27 次注入响应/异常 | 189 是模型接口调用尝试，不全是真实推理 |
| 可观测 token | 输入 74,562；输出 4,414 | 包含核对和修复；27 次注入无真实 usage |
| 正常可回答任务 pipeline P95 | 1,319.65 ms | 无 HTTP、队列、人工审核耗时；不是生产延迟承诺 |

全部场景的混合完成数为 78/108，但场景比例由我们人工设计，不能把 72.2% 称为部署成功率。汇总中的 `candidate_incorrect=9` 实际全部来自主模型超时后的无候选输出：它表示有参考答案但未满足结果检查，不是九个错误 SQL 答案。应拒绝任务没有结果表 oracle，因此 `candidate_unknown=18`，拒绝行为另行评分。

这轮找出了两项实际缺口：核对器误拒正确候选，以及暂态可用性故障没有恢复机制。下一轮如果修改这些行为，必须保留本次基线，并重跑相同协议；不能修改评判标准来掩盖失败。
